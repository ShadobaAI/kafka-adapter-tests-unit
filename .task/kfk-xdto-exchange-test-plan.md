- [ ] W14 Для requiredRows проверить границы 1..3 строки, для fixedStrings — ровно 2 элемента; для singleRow — отрицательную классификацию таблицы при ВерхняяГраница=1. Для stringTable отдельно проверить обёртку с row простого типа, для strings — прямой список.
- [ ] W15 Циклический граф ссылок ИБ задавать в данных теста и проверять через стек выгрузки. Рекурсивная схема допускает конечную вложенность; циклический объект не считать корректным конечным JSON. На неограниченной строке optionalString либо additionalCases.stringLimits.unlimited различать полное совпадение АБ и совпадение только префикса АБВ.
- [ ] W16 При сокращении фикстур сохранять различия, влияющие на поведение: обязательное/необязательное значение, inline/ссылочное перечисление, одиночный/повторяемый элемент, прямой список/таблица с row, вложенность и ограничения. Для даты отдельно проверить необязательный TestConversion.dateTime и обязательный additionalCases.dateTime. Поля с тем же механизмом и теми же признаками не размножать ради количества тестов.

Текущий статус проверки схемы: после сокращения повторов подтверждены разбор YAML, разрешение ссылок, генерация и компиляция временного XSD, сохранность прежних типов пакета. Сохранились все 30 сочетаний примитивного типа/формата, обязательности, наличия enum и видов ограничений, использованных до сокращения; это структурная проверка выбранных признаков, а не доказательство полноты сценариев. Три поля TestConversionStringLimits прошли 13 проверок границ длины. Эти проверки не являются запуском 1С-конвертера; импорт пакета и замер покрытия не выполнялись.

## Подготовка по аналогии

- [ ] Создать декларативный ИсполняемыеСценарии, экспортные серверные тесты `Метод_Поведение`; именованные наборы «Общий модуль кфкОбменДаннымиXDTOСервер. Метод()».
- [ ] Теги набора: Модульные/Интеграционные, кфкОбменДаннымиXDTOСервер, операция; теста — ожидаемое поведение. Параметры регистрировать на уровне теста, отступы fluent-цепочек — по логическому владельцу.
- [ ] Сохранить структуру соседних модулей: интерфейс, нужные hooks, одна служебная область с предметными подразделами. Не создавать отдельную область для каждого теста.
- [ ] Подготовить свежую структуру компонентов на каждый тест: правила, протокол, заголовки и вложенные коллекции не должны переходить в следующий сценарий.
- [ ] Сначала использовать реальные TestCatalog/TestRegister и существующие `кфк_т_ТестовыйСправочник`, `кфк_т_ТестовыйДокумент`, регистры сведений/накопления. Существенные поля задавать явно, регистрацию побочных Kafka-сообщений отключать при подготовке.
- [ ] Подготовить независимые эталонные JSON-сообщения: кириллица, кавычки, пустые/нулевые/ложные значения, три значения перечисления, 0/1/2 строки ТЧ, UUID существующего/несуществующего объекта.
- [ ] Прочитать через unit-edt действующую схему и свойства доступных метаданных перед реализацией типозависимых сценариев. Наличие всех редких типов этим планом не утверждается.
- [ ] Для произвольного формата использовать TestConversion: обязательное/nullable поле, массивы, вложенные объекты, вложенность ≥3 и ограничения. Для общих/ключевых/составных свойств, AdditionalInfo и других специальных ветвей формата 1С использовать EnterpriseData_1_8_6 и его зависимости в base. Сначала проверить существующие типы; EnterpriseData-подобную схему в тестовом YAML не создавать.
- [ ] Учесть, что код использует глобальную ФабрикаXDTO: произвольная схема отдельной локальной фабрики не становится автоматически доступной модулю. Способ размещения тестовой схемы в unit подтвердить через unit-edt.
- [ ] Менеджер обмена — внешняя граница для управляемых результатов обработчиков: по аналогии с двойником Kafka создать при необходимости тестовый менеджер/двойник в unit с журналом вызовов и заранее заданными ответами.
- [ ] Не подменять ФабрикаXDTO, преобразование свойств, выбор ПКО, поиск объектов или запись БД, когда именно эти участки проверяются. У менеджера менять только внешний ответ/обработчик.
- [ ] Неэкспортные методы сначала покрывать через публичный API. Недостижимые через него сценарии — через проверенный минимальный доступ из unit без копирования алгоритма; техническую доступность подтвердить до реализации.
- [ ] Обычные тесты данных — в транзакции по аналогии с тестами регистров. Для внутренних транзакций и отмены проведения отдельно определить совместимость внешней транзакции; при необходимости выделить набор с явной очисткой.
- [ ] Не рассчитывать на автоматическое удаление для изменений существующих объектов. Собственные UUID, контрольные записи, восстановление констант, пометок, движений и кэшей обязательно.
- [ ] Проверять записи через ОжидаетЧтоТаблицаБазы; для документа — сохранённые реквизиты, Проведен и движения, а не только поля незаписанного объекта.
- [ ] Существующие документы покрытия использовать как опыт измерения, а не как текущий результат. Нулевой ответ профайлера требует восстановления измерения, а не объявления 100%.

## Сценарии

Каждый пункт описывает семейство отдельных тестов. Все перечисленные варианты должны получить свои параметры/тесты. Реестр в конце связывает каждую из 171 функций/процедур с предметной группой.

### A. Компоненты и таблицы правил

- [ ] A01 ИнициализироватьКомпонентыОбмена: Отправка/Получение, точное сохранение направления, все исходные поля и типы; пять пользовательских настроек; два вызова не делят коллекции.
- [ ] A02 ИнициализироватьТаблицыПравилОбмена: версия 2/2.КФК/2.кфк, неподдерживаемая 1/3/пустая; основная версия и флаг КФК; EnterpriseData URI с разным регистром и обычный URI; базовая схема SSL добавляется.
- [ ] A03 Вызовы менеджера заполнения ПОД/ПКО/ПКПД/параметров: направление, порядок, фактическое заполнение результата; ошибка каждого вызова.
- [ ] A04 Таблица ПОД: полный набор колонок/типов; 0/1/несколько правил; при Получении неизвестный XDTO удаляется и сохраняется в ОбъектыВыборкиФормата; удаление соседних строк не пропускает вторую; при Отправке имя таблицы по метаданным либо без метаданных; индексы по направлению.
- [ ] A05 EnterpriseData ПОД: нет КлючевыеСвойства, есть без ссылки, есть со ссылкой; правильный ТипСсылкиXDTO.
- [ ] A06 ИнициализироватьПравилоКонвертацииОбъекта и таблица ПКС: добавление строки, новая таблица Свойства, восемь колонок с типами/длинами и два индекса; повторный вызов независим.
- [ ] A07 ИнициализироватьСвойстваТабличныхЧастей: колонка по умолчанию и явно заданная; пять полей, индекс namespace, замена предыдущей таблицы; отсутствие ожидаемой колонки — отрицательный контракт.
- [ ] A08 КоллекцияПравилКонвертации: полный состав колонок из исходника, булевы флаги/таблицы/массивы; после менеджера правильные индексы, получение добавляет индекс ТипСсылкиXDTO.

- [ ] A10 Инициализация ПКО: пустое/базовое/внешнее пространство имён; формат пустой/существует/не найден; удалённое правило помещается в ОбъектыФормата; Отправка/Получение; ОбъектДанных задан/не задан.
- [ ] A11 Тип объекта: документ, справочник, перечисление, регистр, ПВХ, бизнес-процесс, задача, план счетов, план видов расчёта, константа, прочий тип; ровно соответствующие флаги, менеджер, ТипДанных, ПолноеИмя, ЭтоСсылочныйТип. Документ с разрешённым/запрещённым проведением.
- [ ] A12 Параметры получения: стандартные реквизиты включаются только из списка, пользовательские добавляются; пустой/непустой ПоляПоиска, первый вариант представления; три флага обработчиков по пустому/непустому имени.

- [ ] A18 ЗаполнитьСписокСвойствОбъектаXDTO: 0/1/несколько свойств, вложенная группа ОбщиеСвойства и обычный объект; все листья, корректный порядок без потери соседних свойств.

- [ ] D07 ПоместитьВыгруженноеСвойство: корневое ключевое → отдельная структура, простое поле структуры/строки ТЧ, вложенный путь, создание отсутствующей группы.
- [ ] D08 СоздатьТЧПриемникаПоПКС: 0/1/несколько полей, путь с точками, повтор сегмента, повтор обычной колонки, пробелы и пустое имя; ожидаемая таблица либо конкретная ошибка, без молчаливого удаления свойств.
- [ ] D09 ПолучитьЗначениеВложенныхСвойств: пустой путь/один/два/три сегмента; каждый отсутствующий сегмент, скаляр в середине, найденное Неопределено; сохраняется ли исходный выходной параметр при неудаче.
- [ ] D10 ПоместитьЗначениеВложенныхСвойств: структура/строка ТЧ, новая/существующая колонка, новая/существующая группа; пути 2/3/4 сегмента, соседи сохраняются; конфликт со скаляром. Глубина ≥3 обязательна для воспроизведения риска сборки пути.

### E. Формирование XDTO, перечисления и расширения

- [ ] E01 ОбъектФорматаИзДанныхФормата: необязательное nullable одиночное поле и обязательное; источник структура/строка ТЗ/неподдерживаемый; найдено/нет/пусто; флаг ПроведеноЗаполнениеСвойств; исключение содержит тип и имя поля.
- [ ] E02 ТипСвойстваПоИмениИЗначениюСвойства: обычное/массив простого, AdditionalInfo, таблица, ключевые, общие, структура с ТипСоставногоСвойства, общий fallback, неподдерживаемое описание типа.
- [ ] E03 СформироватьЗначениеСвойстваXDTO: все классификации E02; пропуск ненайденного/незаполненного; массив наполняется на месте; неизвестная классификация → Неопределено; результаты не смешиваются.
- [ ] E04 Общая группа: именованная структура существует/нет, источник строка ТЧ; вложенные поля заполнены/нет × ВозможноПустое; обязательная группа создаётся даже без заполненных полей.
- [ ] E05 Обычное значение: UUID/Ref, строка/число/дата/булево, обычная ссылка ИБ через XMLСтрока; перечисление с фасетами; неподходящий тип даёт ошибку реальной фабрики.
- [ ] E06 Таблица XDTO: 0/1/несколько строк и несколько полей; правильный тип строки и порядок. Массив простых: 0/1/несколько, пустые элементы, переключение Null-политики.
- [ ] E07 Составной тип: подходит первый/последний вариант/ни один; структура с совпадающим/другим ТипСоставногоСвойства; обычный тип совпадает/нет; строка без фасетов/с допустимым/недопустимым значением; структура без обязательного поля — отдельная ошибка.
- [ ] E08 Тип простого формата: string/decimal/boolean/date, неподходящие входы, производные имена, различия регистра; нулевое число/Ложь не потеряны при нужной настройке.
- [ ] E09 УстановитьСвойствоОбъектаXDTO: базовый namespace, namespace владельца, внешний; новое свойство добавляется с формой и URI; существующее простое/объектное/табличное.
- [ ] E10 ДополнитьСвойстваОбъектаXDTO: Неопределено пропускается, простое приводится фабрикой, объект рекурсивно дополняется; существующие поля сохраняются согласно реальному контракту.
- [ ] E11 ДополнитьТаблицуОбъектаXDTO: 0/1/несколько строк, одинаковая/разная длина основного и расширяющего списка; соответствие по индексу, ошибка выхода за границу.
- [ ] E12 Перечисление: строковое готовое значение и реальное перечисление; все три значения готового ПКПД; неизвестное значение → ошибка, сообщение содержит тип и значение.
- [ ] E13 НайтиПравилоКонвертацииДляЗначения: 0/1/2 совпадения только по типу и по паре ТипДанных+ТипXDTO; независимость типов назначения; точные диагностические варианты.
- [ ] E14 ЗначениеВСтроку: Null/Неопределено сохраняются, UUID/дата/число/ссылка дают XML-представление; свойства типа массивом сохраняют порядок.
- [ ] E15 ЭтоТаблицаОбъекта/ЭтоТипТаблицыОбъекта: тип значения, объект с 0/1/2 свойствами, единственная строка с верхней границей 1/несколько/-1; ЭтоМассивОбъекта аналогично для простого типа.
- [ ] E16 ЭтоСсылкаXDTO: UUID с разным регистром, Ref, производный и неродственный тип; проверить фактическое направление ЭтоПотомок на реальной схеме.

### F. Валидация схемы и JSON

- [ ] F01 ПроверитьОбъектФорматаПоСхеме: уже ошибка/пропуск → возврат; валидный объект; ошибка фабрики с пустым/непустым подробным стеком; итог содержит ПОД/ПКО/тип.
- [ ] F02 Обязательность: Установлено Ложь × НижняяГраница 0/1/2 × ВозможноПустое; установленное Неопределено; обязательное простое/объектное/список. Отдельно проверить ограничения, которые ручной разбор не объясняет.
- [ ] F03 Простое значение: допустимое и нарушающее ограничения длины/диапазона/перечисления/шаблона; сообщение об ограничениях.
- [ ] F04 Список: пустой/один/несколько, простой/объектный, ошибка первого/среднего/последнего элемента; индексы с 1, вложенность и отступы; валидные элементы не добавляют заголовок ошибки.
- [ ] F05 Вложенный объект: 0/1/несколько ошибок и несколько уровней; полный путь и корректный порядок стека, отсутствие лишних заголовков.
- [ ] F06 СообщениеИзОбъектаXDTO: возвращает разобранное значение, а не сырой JSON; реальные поля и типы, кириллица/спецсимволы; удаление оболочки #value; флаги → Неопределено; ошибка сериализации с заголовком.
- [ ] F07 ОбъектФорматаИзJSON: валидный объект, неизвестный тип, некорректный JSON, неподходящий тип значения, пустая строка/null; правильная оболочка #value и исходная причина ошибки.
- [ ] F08 УдалитьНедопустимыеСимволыJSON: настоящие U+0002/U+0003, их escape-записи, уже экранированные последовательности, b/t/n/f/r после обратной черты, двойное экранирование, обычная кириллица; эталон точного результата и последующее чтение, не только отсутствие ошибки.
- [ ] F09 JSON-экспорт и JSON-импорт проверять независимо на внешних эталонах, затем дополнительно round-trip. Не допускать компенсации двух ошибок симметричной парой собственных преобразователей.

### G. Чтение XDTO в структуру

- [ ] G01 ПрочитатьСообщениеОбмена: пустое имя формата в ПОД, ошибка чтения/преобразования, отсутствие/отключение всех ПКО, выбор первого активного; обработчик меняет ДанныеXDTO; результат записи.
- [ ] G02 ОбъектФорматаВСтруктуру: простые/объектные поля; EnterpriseData ключевые свойства отсутствуют/не структура/структура без ссылки/со ссылкой; копирование ссылки в верхний уровень.
- [ ] G03 КонвертацияСвойстваФорматаВЭлементСтруктуры: неустановлено/чужой namespace → пропуск; заданный/вычисленный тип; Неопределено; переименование составного свойства; ЗначениеXDTO/ОбъектXDTO/список; диагностический заголовок при исключении.
- [ ] G04 AdditionalInfo → реальный десериализатор; таблица → ТаблицаЗначений; ключевые/общие/составные → соответствующие структуры; проверить все ветви ИмяКлассаЗначенияXDTO и приоритет распознавания.
- [ ] G05 КонвертироватьПростоеСвойства: приёмник структура/строка ТЗ с колонкой/без колонки; значение, ссылка и перечисление; отсутствие колонки не повреждает строку.
- [ ] G06 Таблица: список строк 0/1/2, одиночный объект вместо списка, общие вложенные колонки, сохранение порядка/типов/пустых значений.
- [ ] G07 Общие свойства: структура получает вложенную группу и дубли верхнего уровня; строка ТЧ заполняется напрямую; существующее верхнее/ключевое поле не перезаписывается; неизвестное под-свойство пропускается.
- [ ] G08 Ключевые свойства: маркер ЭтоНаборКлючевыхСвойств и ТипЗначения, неизвестное поле пропускается; структура/строка ТЧ как получатель.
- [ ] G09 Составное свойство: неописанное/неустановленное пропускается, используется первый установленный вариант; несколько установленных/ни одного.
- [ ] G10 ПрочитатьЗначениеXDTO: явный/неявный тип, обычное значение/UUID/перечисление; Неопределено с явным типом и без типа отдельно; сложный результат содержит флаги, ТипЗначенияXDTO и Значение.
- [ ] G11 ТипЗначенияСвойстваФормата: нет владельца, базовый namespace свойства, внешний владелец, расширение типа найдено/нет и поле найдено/нет.
- [ ] G12 ИнициализироватьКолонкиТаблицыОбъектаПоТипу: обычные и рекурсивные общие свойства, пустой тип, конфликт имён колонок; отсутствие потерь.

### H. Идентификация объектов

- [ ] H01 КонтекстИдентификации: обрезка пробелов варианта, корректные начальные поля, ссылка отсутствует/есть; EnterpriseData/обычный формат; собственное имя ссылки из ПКС.
- [ ] H02 ПодготовитьСсылку: нессылочный тип → без действий; нет поля ссылки/вариант не по UUID → новая ссылка; валидный/пустой/неверный UUID; ссылка существует/нет.
- [ ] H03 ПолучитьСсылку + ПоУникальномуИдентификатору: существующая ссылка возвращается без записи; несуществующая возвращается как ссылка, объект не создаётся. Комбинированный вариант при отсутствии объекта продолжает поиск по полям.
- [ ] H04 Полная загрузка с UUID: существующий объект обновляется, новый получает исходный UUID; повтор не создаёт дубликат; EnterpriseData извлекает .Значение, обычный формат — строковый UUID.
- [ ] H05 ИдентифицироватьПолученныеДанныеПоПолям: объект уже найден, регистр и иной вариант — поиск пропускается; найдено/не найдено; ПолучитьСсылку возвращает ссылку, полная загрузка получает объект.
- [ ] H06 ПоляПоиска Неопределено/не массив/пустой/несколько вариантов; обязательное поле незаполнено → вариант пропускается; пустой Родитель допустим для справочника/ПВХ и недопустим для других типов.
- [ ] H07 Платформенный поиск: документ строго по Дата+Номер, справочник строго по Наименование или Код; найдено/пустая ссылка; дополнительное поле переводит в запрос; точное совпадение имени.
- [ ] H08 Смешанные варианты: сначала запрос затем платформенный, наоборот; успешен один/оба/ни один; минимальный номер приоритета выигрывает; первый успешный платформенный поиск не подавляет более ранний запросный вариант.
- [ ] H09 Запрос: 0/1/несколько вариантов, несколько полей через И, разные параметры без коллизий, несколько результатов; нижний приоритет выбирается независимо от порядка результатов; одинаковый приоритет/дубли — характеризовать без обещания устойчивого выбора конкретной ссылки.
- [ ] H10 УсловиеОтбораПоПолю: ограниченная/неограниченная строка, число, дата, ссылка; для неограниченной строки ВЫРАЗИТЬ с длиной значения; совпадающий префикс более длинной строки — обязательная проверка ложного совпадения.
- [ ] H11 СсылкаПоУИД: тип ссылки сохранён, существующий/несуществующий/пустой UUID, некорректный UUID; отсутствие создания записи только от получения ссылки.
- [ ] H12 Для режимов КонвертироватьИЗаписать/ПолучитьСсылку/прочее проверить возвращаемый тип и наличие записи отдельно: имя действия не доказывает отсутствие записи при поиске по полям.

### I. Конвертация полученных свойств и табличных частей

- [ ] I01 СтруктураОбъектаФорматаВДанныеИБ: порядок два этапа → обработчик → идентификация → запись; Только свойства поиска не конвертирует ТЧ; EnterpriseData временно оборачивает ключевые данные и восстанавливает их.
- [ ] I02 ИнициализироватьПолученныеДанные: документ, элемент/группа справочника и ПВХ, регистр, бизнес-процесс, задача, план счетов, план видов расчёта; неподдерживаемый тип → Неопределено. Все редкие типы требуют фактически доступной фикстуры.
- [ ] I03 КонвертироватьСвойстваШапки: Все/СвойстваПоиска, помеченные/непомеченные поля; пустое СвойствоКонфигурации и Ссылка не присваиваются.
- [ ] I04 Первый этап свойства: пустой формат; ключевые EnterpriseData внутри группы/ЭтоНаборКлючевыхСвойств; простой/вложенный путь; отсутствие обычного/ключевого/алгоритмического поля; список отсутствующих создаётся и дополняется.
- [ ] I05 Второй этап: правильный/неправильный номер, флаг алгоритма, значение в допсвойствах шапки/строки; поле отсутствует; индекс по НомерСтроки; отсутствие чужих значений.
- [ ] I06 Null/Неопределено/0/Ложь/пустая строка и заполненное значение: проверить сохранение/обнуление существующего реквизита, а не только загрузку нового; ветвь Не ЗначениеЗаполнено сейчас возвращает без присваивания.
- [ ] I07 РазобратьИнструкциюПолучения: не структура; только одно из ИмяПКО/Значение; оба; дополнительный флаг удаления отсутствует/Ложь/Истина; корректные выходные параметры.
- [ ] I08 Предопределённое значение: ПКПД нет → продолжить ПКО; есть + отображение есть/нет; правильное поле получателя; неизвестное значение не должно незаметно стать успешным.
- [ ] I09 Вложенная ссылка через ПКО: найденное/новое значение, ПолучитьСсылку, заполнение реквизита; проверить форму параметра ПравилоКонвертации и доступность УдалятьСозданныеПоКлючевымСвойствам в компонентах.
- [ ] I10 Первый этап ТЧ: номер этапа, пустое имя стороны, ТЧ отсутствует/пуста/1/2 строки; алгоритмические поля пропускаются; собственный объект строки, правильный порядок.
- [ ] I11 Второй этап ТЧ: каждое условие запуска отдельно, 0/1/несколько структур; строк меньше/равно/больше имеющихся; существующие обновляются, новые добавляются; только алгоритмические ПКС.
- [ ] I12 Любая ошибка преобразования включает имя реквизита и общий заголовок; исходная причина не теряется, последующие записи не выдаются за успешные.

### J. Запись и обновление ИБ

- [ ] J01 ЗаписатьПолученныеДанныеВИБ: полная/ссылочная загрузка, РазрешитьСоздаватьОбъектИзСтруктуры Истина/Ложь, существующий/новый объект; ПередЗаписью только при условии полной загрузки и наличии обработчика.
- [ ] J02 ПодготовитьДанныеДляЗаписиВИБ: нет ДанныеИБ → полученные данные; существующий объект + полученные данные → копирование; полученные Неопределено → существующий без копирования; оба отсутствуют → возврат без записи.
- [ ] J03 ЗаполнитьДанныеИБПоПолученнымДанным: только поля ПКС, пробелы в именах, 0 полей, отсутствующие данные исключены; разные имена СвойствоФормата и СвойствоКонфигурации; контрольные реквизиты вне правил сохранены.
- [ ] J04 ТЧ существующего объекта: пустое имя пропускается; полная замена и очистка старых строк; пустая/неприсланная ТЧ отдельно — ожидаемое сохранение/очистку согласовать с контрактом, не путать случаи.
- [ ] J05 Генерация: документ/бизнес-процесс/задача с пустым/заданным номером; справочник/ПВХ с пустым/заданным кодом × Автонумерация; прочие типы без изменения.
- [ ] J06 ПометкаУдаления: обычный ссылочный объект снимается при загрузке; предопределённый помеченный объект на прямом пути записи снимает флаг и выдаёт ошибку; 4 сочетания двух флагов.
- [ ] J07 УстановитьОбменДаннымиЗагрузка: оба значения Загрузка; ОтключитьМеханизмРегистрации Истина/Ложь, допсвойство есть/нет; вызов кфкИнтеграция.Отключить и отсутствие побочной регистрации.
- [ ] J08 ЗаписатьОбъектВИБ: успех и реальная ошибка записи × ИспользоватьТранзакции Истина/Ложь; подтверждённый commit/rollback по состоянию БД; чужие данные неизменны; ошибка содержит первопричину.
- [ ] J09 Документ не может проводиться → обычная запись; может проводиться × входной Проведен × новый/существующий × Проведен в БД; проверить итоговое Проведен и движения. Текущий код снимает проведение, не обещать автоматическое проведение после загрузки.
- [ ] J10 ОтменитьПроведениеОбъектаВИБ: свойство очистки движений отсутствует/есть; вариант явной ОтменаПроведения Истина/Ложь/отсутствует; настройка Загрузка до/после, обычная запись и удаление движений; успех/ошибка, транзакция включена/выключена.
